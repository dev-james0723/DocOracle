## 実例：病院が内部医療知識ベースを構築したい

ある病院が 600 ページの「救急医学ハンドブック」（PDF 形式）を持っているとします。医師が毎回本を調べるのではなく、AI チャットインターフェースを通じてすばやく検索できるようにしたいと考えています。

病院の IT 部長が DocOracle を使うことにしました。以下は、各ステップでの操作内容と表示される画面です。

---

## ステップ 1：まずライブデモを試す（インストール不要）

何もインストールする前に、IT 部長は DocOracle ライブデモにアクセスします：**[decca-oracle.manus.space](https://decca-oracle.manus.space)**。

ランディングページには 2 つのオプションが表示されます：

- **「デモを探索」** — 事前に処理されたサンプル文書を読み込み、何もアップロードせずにナレッジハブの外観をすぐに確認できます。
- **「あなたの PDF で試す」** — 自分の PDF をアップロードして、完全なパイプラインを実行できます。

IT 部長は **「あなたの PDF で試す」** をクリックし、ハンドブックの 50 ページの抜粋をアップロードして待ちます。

---

## ステップ 2：アップロードとパイプライン処理画面

アップロード後、ユーザーは **最近のアップロード** 画面に移動します。この画面には、送信されたすべての PDF と現在の処理状態が表示されます。

リストの各項目には以下が表示されます：

| 列 | 意味 |
|----|------|
| **ファイル名** | アップロードされた PDF の名前 |
| **ステータスバッジ** | `キュー待ち`、`処理中`、`完了`、`失敗` のいずれか |
| **「進捗を確認」ボタン** | そのアップロードのジョブ詳細ページを開く |
| **ゴミ箱アイコンボタン** | ジョブを即座に削除する（すべてのステータスで利用可能） |

> **ライブデモの実例：** *Emergency_Medicine_Excerpt.pdf* をアップロードした後、最近のアップロードリストには以下が表示されます：
>
> ```
> Emergency_Medicine_Excerpt.pdf   [処理中]   [進捗を確認]  [🗑]
> ```

ゴミ箱アイコン（🗑）は「進捗を確認」ボタンの**左側**に表示されます。キュー待ちや処理中のジョブを含め、いつでも任意のジョブを削除して、API クレジットの消費を防ぐことができます。

---

**「進捗を確認」** をクリックすると、ジョブ詳細ページが開きます。パイプライン実行中は、12 のステップのうち現在どのステップが実行されているかを示すリアルタイムの進捗インジケーターが表示されます：

  - 11〜20 ページを処理中...

処理時間は文書のサイズによって異なります：

## ステップ 4：パイプラインが失敗した場合の対処法

Gemini API のレート制限に達した場合や、PDF に異常なエンコーディングが含まれている場合など、パイプラインが失敗することがあります。この場合、ジョブ詳細ページには明確な **「パイプライン失敗」** エラーカードが表示されます。

カードには 2 つのボタンが並んで表示されます：

- **「再試行」** — ジョブを再キューに入れ、パイプラインを最初から再試行します。
- **「削除」** — ジョブをシステムから永久に削除します。

> **「削除」ボタンが重要な理由：** ジョブが繰り返し失敗する場合、「再試行」をクリックし続けると、結果が出ないまま API クレジットを消費し続けます。「削除」ボタンを使えば、失敗したジョブをきれいに削除して、バックグラウンドでの再試行を防ぐことができます。

**実例：** IT 部長が誤って破損した PDF をアップロードしました。パイプラインはステップ 2 で失敗しました。「再試行」（また失敗する）をクリックする代わりに、**「削除」** をクリックして、正しいファイルを再アップロードしました。

## ステップ 5：ナレッジハブ — パイプライン完了後に表示される画面

これがこのガイドで最も重要な部分です。パイプラインが正常に完了すると、ジョブ詳細ページは **ナレッジハブ（Knowledge Hub）** に変わります — 3 つのタブを持つ完全なインターフェースです。

### 統計バー

ナレッジハブの上部にある統計バーには、抽出されたコンテンツの概要が表示されます：

```
📄 50 ページ   |   🖼 12 個の視覚アセット   |   📑 8 つのセクション   |   📖 23 の用語
```

### タブ 1：書籍構造

**書籍構造**タブには、文書の完全な章とセクションの階層が表示されます。各エントリには以下が表示されます：

- セクションのタイトルとページ範囲（例：「第 3 章：胸痛評価 — 42〜67 ページ」）
- そのセクションの内容の 1 段落の要約
- キーワードタグ（例：`心電図`、`トロポニン`、`鑑別診断`）

**任意のセクションをクリックする**と、そのセクションに関する事前入力されたチャット質問が開きます。例えば、「第 3 章：胸痛評価」をクリックすると、自動的に「第 3 章は胸痛評価についてどのような内容を扱っていますか？」という質問が送信されます。

> **ライブデモの実例：** IT 部長は「第 5 章：外傷プロトコル」を参照してクリックしました。AI はすぐにハンドブックの具体的なページを引用した構造化された要約で回答しました。

### タブ 2：用語集

**用語集**タブには、文書から抽出されたすべての専門用語が検索可能なカードとして表示されます。各カードには以下が表示されます：

- 用語（例：「トロポニン I」）
- 文書から抽出された定義
- 登場するページ番号
- カテゴリバッジ（例：`バイオマーカー`、`診断`）

用語集タブの上部には**検索バー**があります。「心電図」と入力すると、心電図に関連する用語のみが表示されるようにリストがフィルタリングされます。

**任意の用語カードをクリックする**と、事前入力されたチャット質問が開きます。例えば、「トロポニン I」をクリックすると「トロポニン I についてもっと詳しく説明してもらえますか？」という質問が送信されます。

> **ライブデモの実例：** ある医師が用語集タブを使って「STEMI」（ST 上昇型心筋梗塞）を調べました。カードには定義、ページ範囲（246〜251 ページ）、`心臓病学` バッジが表示されました。カードをクリックすると詳細を求めるチャットが開き、AI は 246、248、250 ページを引用した完全な説明で回答しました。

### タブ 3：質問を始める

**質問を始める**タブには、文書のコンテンツから生成された 6 つの推奨質問が表示されます。これらは、新しいユーザーが DocOracle でどのような質問ができるかを理解するのに役立ちます。

救急医学ハンドブックの推奨質問の例：

1. 「アナフィラキシーの一次治療は何ですか？」
2. 「意識状態が変化した患者をどのように評価すればよいですか？」
3. 「肺塞栓症が疑われる場合、どのような画像検査が推奨されますか？」
4. 「外傷チームを起動する基準は何ですか？」
5. 「STEMI の 12 誘導心電図をどのように解釈しますか？」
6. 「妊娠中の緊急事態で禁忌となる薬剤は何ですか？」

推奨質問をクリックすると、AI チャットに直接送信されます。

## ステップ 6：AI チャットの使用

ナレッジハブのタブを探索した後、医師は推奨質問の 1 つをクリックするか、自分で入力します。AI の回答には以下が含まれます：

1. 文書に基づいた構造化された回答
2. 正確なページ番号の引用
3. 回答の横に自動的に表示される関連図表や表

**実際の会話例：**

> **医師：**「患者に重篤な胸痛がある場合、どのような検査を行うべきですか？」
>
> **DocOracle AI：**「ハンドブック（245〜250 ページ）によると、重篤な胸痛を呈する患者には以下の検査が推奨されます：
>
> 1. **心電図（ECG）** — 到着後 10 分以内に実施。解釈ガイドラインは 246 ページを参照。
> 2. **胸部 X 線** — 気胸と大動脈解離を除外するため。248 ページを参照。
> 3. **血液検査** — トロポニン I、BNP、D ダイマー。基準値は 250 ページを参照。
>
> [図表：心電図解釈フローチャート — 247 ページから抽出]
>
> [ボタン：**画像説明に変換** — クリックしてこの回答の視覚的要約を生成]」

**「画像説明に変換」**ボタンをクリックすると、回答を要約した AI 作成の視覚的な図が生成されます — クイックリファレンスや教育目的に役立ちます。

## ステップ 7：アップロードの管理

### 最近のアップロードリストからジョブを削除する

DocOracle のメインページの **最近のアップロード** セクションには、処理されたすべての文書が一覧表示されます。各行の「進捗を確認」ボタンの左側にゴミ箱アイコン（🗑）ボタンがあります。

**すべてのステータスのジョブ**を削除できます：

| ステータス | 削除可能？ | 効果 |
|-----------|-----------|------|
| `キュー待ち` | はい | 開始前にジョブをキャンセル |
| `処理中` | はい | パイプラインを途中で停止 |
| `完了` | はい | 知識ベースを永久に削除 |
| `失敗` | はい | 失敗したジョブをクリーンアップ |

> **これが重要な理由：** 削除されていない失敗したジョブは自動的に再試行され、API クレジットを消費する可能性があります。すぐに削除することでこれを防ぎます。

### ジョブ詳細ページからジョブを削除する

特定のジョブ（成功・失敗を問わず）を表示しているとき、そのページにも**削除**ボタンがあります：

- **完了**したジョブの場合：削除ボタンはナレッジハブのヘッダーに、文書タイトルの横に表示されます。
- **失敗**したジョブの場合：削除ボタンはエラーカード内の「再試行」ボタンの横に表示されます。

## ステップ 8：独自のインスタンスをデプロイする（開発者向け）

独自のサーバーで独自の文書を使って DocOracle を実行したい場合は、以下の手順に従ってください。

### 前提条件

| 要件 | バージョン | 用途 |
|------|-----------|------|
| Python | 3.9+ | パイプラインスクリプト |
| Node.js | 18+ | ウェブサイト |
| pdftotext | 任意 | テキスト抽出（`sudo apt-get install poppler-utils`） |
| Gemini API キー | — | Vision 分析とチャット（[無料キーを取得](https://aistudio.google.com/app/apikey)） |

### 手順

**1. リポジトリをクローン**

```bash
git clone https://github.com/dev-james0723/DocOracle.git
cd DocOracle
```

**2. PDF を `input/` フォルダに配置**

```bash
cp /path/to/your/handbook.pdf input/
```

**3. パイプラインの依存関係をインストール**

```bash
pip install -r pipeline/requirements.txt
```

**4. Gemini API キーを設定**

```bash
export GEMINI_API_KEY="your-gemini-api-key"
```

**5. パイプラインを実行**

```bash
bash pipeline/run_all.sh
```

**6. 出力ファイルをウェブサイトにコピー**

```bash
cp output/05_retrieval/page_chunks.jsonl website/server/data/
cp output/04_gold_master/glossary.json website/server/data/
cp output/04_gold_master/sections.json website/server/data/
cp output/10_visual_assets/visual_assets_index.json website/server/data/visual_assets.json
```

**7. ウェブサイトを起動**

```bash
cd website
npm install
npm run dev
```

ブラウザで `http://localhost:3000` を開きます。AI 知識ベースの準備完了です。

## よくある質問

**Q：パイプラインにはどのくらい時間がかかりますか？**
A：50 ページの文書で約 15 分、200 ページで約 1 時間、500 ページで約 3 時間です。処理時間は視覚アセット（図表、表）の数によって異なります。各アセットは Gemini Vision によって個別に分析されます。

**Q：Gemini API の料金は発生しますか？**
A：Gemini には小さな文書（最大約 50 ページ）をカバーする無料枠があります。大きな文書には有料の API キーが必要になる場合があります。現在の料金については [Google AI Studio](https://aistudio.google.com) をご確認ください。

**Q：Gemini 以外の LLM を使用できますか？**
A：はい。`pipeline/config.yaml` を編集して別のモデルエンドポイントを指定します。パイプラインのテキストステップはモデルに依存しない設計になっています。Vision 分析ステップのみマルチモーダルモデルが必要です。

**Q：パイプラインが途中で失敗した場合はどうなりますか？**
A：パイプラインは各ステップで進捗を保存します。ステップ 7 で失敗した場合、ステップ 1〜6 を繰り返すことなくステップ 7 から再実行できます。または、UI からジョブを削除して最初からやり直すこともできます。

**Q：完了した知識ベースを削除できますか？**
A：はい。最近のアップロードリストのゴミ箱アイコン、またはジョブ詳細ページの削除ボタンを使用します。これにより、ジョブとすべての関連データが永久に削除されます。

**Q：どのファイル形式がサポートされていますか？**
A：現在は PDF のみです。将来のリリースで DOCX、EPUB、HTML のサポートが予定されています。

## まとめ：ユーザーが利用できる機能

文書に DocOracle を実行した後、ユーザーは以下の機能を利用できます：

| 機能 | 説明 |
|------|------|
| **引用付き AI チャット** | 質問して、正確なページ番号付きの回答を取得 |
| **書籍構造タブ** | 章とセクションを閲覧；クリックして質問 |
| **用語集タブ** | 抽出されたすべての用語を検索；クリックして詳細を要求 |
| **質問を始めるタブ** | 文書から生成された 6 つの推奨質問 |
| **視覚アセット検索** | 関連する図表が回答の横に自動表示 |
| **画像説明** | 複雑な回答の視覚的要約を生成 |
| **削除コントロール** | いつでも任意のジョブを削除（キュー待ち、処理中、完了、失敗） |

---

*DocOracle — すべての文書は理解される価値がある。*
