## 真實範例：一間醫院建立內部醫學知識庫

假設某醫院擁有一本 600 頁的《急診醫學手冊》（PDF 格式），希望讓醫師能夠透過 AI 聊天介面快速查詢，而無需每次翻閱實體書籍。

醫院的 IT 主管決定採用 DocOracle。以下詳細說明每一個操作步驟及對應的畫面。

---

## 第一步：先試用線上演示（無需安裝）

在安裝任何軟體之前，IT 主管先前往 DocOracle 線上演示：**[decca-oracle.manus.space](https://decca-oracle.manus.space)**。

首頁提供兩個選項：

- **「探索演示」** — 載入預先處理完成的範例文件，讓使用者無需上傳任何內容，即可立即預覽知識庫的完整介面。
- **「使用您的 PDF 試用」** — 允許使用者上傳自己的 PDF，並對其執行完整的處理流程（Pipeline）。

IT 主管點擊 **「使用您的 PDF 試用」**，上傳手冊的 50 頁節錄，然後等待處理完成。

---

## 第二步：上傳與 Pipeline 處理畫面

上傳完成後，使用者將進入 **最近上傳** 畫面。此畫面顯示所有已提交的 PDF 及其當前處理狀態。

清單中的每個項目包含以下資訊：

| 欄位 | 說明 |
|------|------|
| **檔案名稱** | 已上傳 PDF 的名稱 |
| **狀態標籤** | 顯示為以下其中一種：`排隊中`、`處理中`、`已完成`、`失敗` |
| **「查看進度」按鈕** | 開啟該上傳項目的工作詳情頁面 |
| **垃圾桶圖示按鈕** | 立即刪除該工作（適用於所有狀態） |

> **線上演示的真實範例：** 上傳 *Emergency_Medicine_Excerpt.pdf* 後，最近上傳清單顯示如下：
>
> ```
> Emergency_Medicine_Excerpt.pdf   [處理中]   [查看進度]  [🗑]
> ```

垃圾桶圖示（🗑）位於「查看進度」按鈕的**左側**。使用者可隨時刪除任何工作，包括仍在排隊或正在處理中的工作，以防止其繼續消耗 API 額度。

## 第四步：Pipeline 失敗時的處理方式

在某些情況下，Pipeline 可能會失敗，例如 Gemini API 達到速率限制，或 PDF 包含異常編碼。發生此情況時，工作詳情頁面將顯示明確的 **「Pipeline 失敗」** 錯誤卡片。

卡片上並排顯示兩個按鈕：

- **「重新嘗試」** — 將工作重新加入佇列，從頭開始執行 Pipeline。
- **「刪除」** — 將該工作從系統中永久移除。

> **「刪除」按鈕的重要性：** 若工作反覆失敗，持續點擊「重新嘗試」將不斷消耗 API 額度而無法產生任何結果。「刪除」按鈕可讓使用者乾淨地移除失敗的工作，防止其在背景持續重試。

**真實範例：** IT 主管誤上傳了一個損壞的 PDF 檔案，Pipeline 在步驟 2 時失敗。主管未點擊「重新嘗試」（因為再次嘗試仍會失敗），而是直接點擊 **「刪除」**，然後重新上傳正確的檔案。

## 第五步：知識庫中心 — Pipeline 完成後的介面

這是本指南最核心的部分。Pipeline 成功完成後，工作詳情頁面將轉變為 **知識庫中心（Knowledge Hub）**，呈現包含三個分頁的完整介面。

### 統計欄

知識庫中心頂部的統計欄顯示已提取內容的概要數據：

```
📄 50 頁   |   🖼 12 個視覺資產   |   📑 8 個章節   |   📖 23 個詞彙
```

### 分頁一：書籍結構

**書籍結構**分頁呈現文件的完整章節與段落層次結構。每個條目包含：

- 章節標題與頁碼範圍（例如：「第三章：胸痛評估 — 第 42–67 頁」）
- 該章節內容的段落摘要
- 關鍵主題標籤（例如：`心電圖`、`肌鈣蛋白`、`鑑別診斷`）

**點擊任一章節**，系統將自動開啟一個針對該章節的預填聊天問題。例如，點擊「第三章：胸痛評估」後，系統將自動送出：*「第三章關於胸痛評估涵蓋了哪些內容？」*

> **線上演示的真實範例：** IT 主管瀏覽至「第五章：創傷處理方案」並點擊。AI 隨即以結構化摘要作出回應，並引用了手冊中的具體頁碼。

### 分頁二：詞彙表

**詞彙表**分頁以可搜尋的卡片形式，呈現從文件中提取的所有專業術語。每張卡片包含：

- 術語名稱（例如：「肌鈣蛋白 I」）
- 從文件中提取的定義
- 術語出現的頁碼
- 類別標籤（例如：`生物標誌物`、`診斷`）

詞彙表分頁頂部設有**搜尋欄**。輸入「心電圖」後，清單將自動篩選，僅顯示與心電圖相關的術語。

**點擊任一詞彙卡片**，系統將開啟一個預填聊天問題。例如，點擊「肌鈣蛋白 I」後，系統將送出：*「請進一步說明肌鈣蛋白 I 的相關資訊。」*

> **線上演示的真實範例：** 一位醫師使用詞彙表分頁查找「STEMI」（ST 段抬高型心肌梗死）。卡片顯示了定義、頁碼範圍（第 246–251 頁）及 `心臟病學` 類別標籤。點擊卡片後，系統開啟了一個要求進一步說明的聊天對話，AI 隨即以引用第 246、248 及 250 頁的完整解釋作出回應。

### 分頁三：開始提問

**開始提問**分頁顯示根據文件內容自動生成的 6 個建議問題，協助新使用者了解 DocOracle 所能回答的問題類型。

以《急診醫學手冊》為例，建議問題如下：

1. 「過敏反應的一線治療方案為何？」
2. 「如何評估意識狀態改變的患者？」
3. 「疑似肺栓塞時，建議進行哪些影像學檢查？」
4. 「啟動創傷團隊的判斷標準為何？」
5. 「如何解讀 12 導聯心電圖中的 STEMI 表現？」
6. 「妊娠期緊急情況中，哪些藥物屬於禁忌？」

點擊任一建議問題，即可直接將其送至 AI 聊天介面。

## 第六步：使用 AI 聊天功能

探索知識庫中心各分頁後，醫師可點擊建議問題或自行輸入查詢。AI 的回應將包含以下內容：

1. 以文件為依據的結構化答案
2. 精確的頁碼引用
3. 自動顯示於答案旁的相關圖表或表格

**真實對話範例：**

> **醫師：**「若患者出現嚴重胸痛，應進行哪些檢查？」
>
> **DocOracle AI：**「根據手冊（第 245–250 頁），對於嚴重胸痛的患者，建議進行以下檢查：
>
> 1. **心電圖（ECG）** — 應於患者到達後 10 分鐘內完成。解讀指引請參閱第 246 頁。
> 2. **胸部 X 光** — 用於排除氣胸及主動脈剝離。請參閱第 248 頁。
> 3. **血液檢查** — 包括肌鈣蛋白 I、BNP 及 D-二聚體。參考值範圍請見第 250 頁。
>
> [圖表：心電圖解讀流程圖 — 擷取自第 247 頁]
>
> [按鈕：**轉換為圖片說明** — 點擊以生成此答案的視覺化摘要]」

**「轉換為圖片說明」**按鈕可生成由 AI 建立的視覺圖表，以圖像形式呈現答案摘要，適合快速參考或教學用途。

## 第七步：管理上傳項目

### 從最近上傳清單刪除工作

在 DocOracle 主頁面的 **最近上傳** 區塊，列出所有已處理的文件。每一列在「查看進度」按鈕左側均設有垃圾桶圖示（🗑）按鈕。

使用者可刪除**任何狀態的工作**：

| 狀態 | 可否刪除 | 執行效果 |
|------|---------|---------|
| `排隊中` | 是 | 在工作開始前取消 |
| `處理中` | 是 | 中止 Pipeline 執行 |
| `已完成` | 是 | 永久移除知識庫 |
| `失敗` | 是 | 清除失敗的工作記錄 |

> **重要提示：** 未刪除的失敗工作可能會自動重試，持續消耗 API 額度。建議立即刪除，以避免不必要的資源消耗。

### 從工作詳情頁面刪除工作

在查看特定工作（無論成功或失敗）時，該頁面亦設有**刪除**按鈕：

- **已完成**的工作：刪除按鈕位於知識庫中心標題欄，緊鄰文件標題。
- **失敗**的工作：刪除按鈕位於錯誤卡片內，緊鄰「重新嘗試」按鈕。

## 第八步：部署自有實例（開發者路徑）

若需在自有伺服器上以自有文件執行 DocOracle，請依照以下步驟操作。

### 先決條件

| 需求 | 版本 | 用途 |
|------|------|------|
| Python | 3.9+ | Pipeline 腳本 |
| Node.js | 18+ | 網站 |
| pdftotext | 任意版本 | 文字提取（`sudo apt-get install poppler-utils`） |
| Gemini API 金鑰 | — | Vision 分析與聊天功能（[取得免費金鑰](https://aistudio.google.com/app/apikey)） |

### 逐步操作說明

**1. 複製儲存庫**

```bash
git clone https://github.com/dev-james0723/DocOracle.git
cd DocOracle
```

**2. 將 PDF 放入 `input/` 資料夾**

```bash
cp /path/to/your/handbook.pdf input/
```

**3. 安裝 Pipeline 相依套件**

```bash
pip install -r pipeline/requirements.txt
```

**4. 設定 Gemini API 金鑰**

```bash
export GEMINI_API_KEY="your-gemini-api-key"
```

**5. 執行 Pipeline**

```bash
bash pipeline/run_all.sh
```

**6. 將輸出檔案複製至網站目錄**

```bash
cp output/05_retrieval/page_chunks.jsonl website/server/data/
cp output/04_gold_master/glossary.json website/server/data/
cp output/04_gold_master/sections.json website/server/data/
cp output/10_visual_assets/visual_assets_index.json website/server/data/visual_assets.json
```

**7. 啟動網站**

```bash
cd website
npm install
npm run dev
```

在瀏覽器中開啟 `http://localhost:3000`，即可使用 AI 知識庫。

## 常見問題

**問：Pipeline 需要多長時間？**
答：50 頁文件約需 15 分鐘，200 頁約需 1 小時，500 頁約需 3 小時。處理時間取決於視覺資產（圖表、表格）的數量，因為每個資產均由 Gemini Vision 單獨分析。

**問：使用 Gemini API 是否需要付費？**
答：Gemini 提供免費方案，適用於小型文件（最多約 50 頁）。處理較大文件時，可能需要付費 API 金鑰。請參閱 [Google AI Studio](https://aistudio.google.com) 了解最新定價資訊。

**問：可以使用 Gemini 以外的語言模型嗎？**
答：可以。編輯 `pipeline/config.yaml` 以指向不同的模型端點。Pipeline 的文字處理步驟設計為模型無關；僅 Vision 分析步驟需要多模態模型。

**問：若 Pipeline 中途失敗，應如何處理？**
答：Pipeline 在每個步驟均會儲存進度。若在步驟 7 失敗，可從步驟 7 重新執行，無需重複步驟 1–6。亦可從介面刪除工作後重新開始。

**問：可以刪除已完成的知識庫嗎？**
答：可以。使用最近上傳清單中的垃圾桶圖示，或工作詳情頁面上的刪除按鈕，即可永久移除工作及所有相關資料。

**問：目前支援哪些檔案格式？**
答：目前僅支援 PDF 格式。DOCX、EPUB 及 HTML 的支援將於未來版本中加入。

## 總結：使用者可使用的功能

對文件執行 DocOracle 後，使用者可存取以下功能：

| 功能 | 說明 |
|------|------|
| **附引用的 AI 聊天** | 提問並獲得附精確頁碼的答案 |
