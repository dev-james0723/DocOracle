# DocOracle

**あらゆる PDF を AI 知識ベースに変換 — チャット、図表、引用、デプロイ可能なウェブサイト付き。**

DocOracle はオープンソースプロジェクトで、あらゆる PDF ドキュメントを完全に構造化された AI 知識ベースへと変換します。すべてのページからテキストを抽出し、Gemini Vision ですべての図表を分析し、検索可能なデータを構築します。さらに、ユーザーが質問して原文書に基づいた回答を得られるインタラクティブなウェブサイトを自動生成します — すべての回答にページレベルの引用と関連図表が表示されます。

## なぜ DocOracle なのか？（PDF を ChatGPT にアップロードするだけではダメなのか？）

こう思うかもしれません：*「ChatGPT や Claude に PDF をアップロードして質問すればいいのでは？」*

確かにそれも可能です — しかし、その場合に起こることを比較してみましょう：

| | PDF を ChatGPT/Claude にアップロード | DocOracle |
|---|---|---|
| **ページ引用** | 曖昧または欠如 — LLM は回答がどのページから来ているかを確実に伝えられない | パイプラインがページ境界を保持するため、すべての回答に正確なページ番号が含まれる |
| **図表・画像** | 無視または不十分な説明 — ほとんどの LLM は視覚コンテンツを完全にスキップする | すべての図表、表、写真が Gemini Vision によって詳細な空間的説明と検索タグで分析される |
| **大型ドキュメント（200+ ページ）** | コンテキストウィンドウのオーバーフロー — LLM はコンテンツを静かに削除し、不完全または幻覚的な回答を生成する | パイプラインはすべてのページを個別に処理し、検索最適化されたチャンクを構築 — コンテンツは失われない |
| **一貫性** | 同じ質問をするたびに異なる回答が返ってくる可能性がある | 構造化された JSON データにより確定的な検索が保証される — 同じ質問は常に同じ根拠を見つける |
| **再利用性** | 単一のチャットセッションに閉じ込められる — 共有、検索、または発展させることができない | 出力は標準 JSON ファイルで、ウェブサイトを動かしたり、RAG システムに供給したり、あらゆるアプリケーションに統合できる |
| **用語集と構造** | なし — ナビゲーションのない生の回答のみ | カテゴリバッジ付きの自動生成用語集、要約とキーワードタグ付きの章/セクションナビゲーター |
| **共有可能な成果物** | プライベートなチャットスレッド | チームメンバー、読者、学生、または顧客が使用できるデプロイ可能なウェブサイト |

要するに、PDF を LLM にアップロードすることで得られるのは**使い捨ての会話**です。DocOracle が提供するのは、すべてのページ、すべての図表、すべての引用を保持した**永続的で構造化された共有可能な知識ベース**です。

## 誰のためのツールか？

DocOracle は、技術的な背景と目標に応じて、さまざまなタイプのユーザーにサービスを提供します。あなたに当てはまるカテゴリをお読みください。

### カテゴリ 1 — 非技術ユーザー（コーディング不要）

このカテゴリのユーザーは、コードを書いたりスクリプトを実行したりせずに PDF を AI 知識ベースに変換したいと考えています。

#### 1.1 ライブデモを試す（ゼロセットアップ）

**あなたは：** PDF を持っていて、何もインストールせずに DocOracle をすぐに試したい方。

**やること：** [DocOracle ライブデモ](https://decca-oracle.manus.space)にアクセスし、「あなたの PDF で試す」をクリックし、ドキュメントをアップロードして、パイプラインの処理が完了するまで待ちます。完了したら、ブラウザで直接 AI とドキュメントについてチャットできます — 引用と図表付きで。

**必要なもの：** ウェブブラウザと PDF ファイル。それだけです。

> これは DocOracle を体験する最も速い方法です。ダウンロード不要、ターミナル不要、API キー不要。

#### 1.2 スタンドアロン AI 知識ベースウェブサイトを構築する（ノーコードツール）

**あなたは：** [Base44](https://base44.com)、[Lovable](https://lovable.dev)、[Vibecoding.ai](https://vibecoding.ai)、または [Cursor](https://cursor.sh) などの AI 駆動ウェブビルダーを使用するユーザーで、PDF から独自の AI 知識ベースウェブサイトを構築したい方。

**やること：** DocOracle パイプラインを実行し（または AI エージェントに実行させる — [カテゴリ 2](#カテゴリ-2--開発者・技術ユーザー) を参照）、PDF を 4 つの JSON データファイルに処理します。次に、お好みのノーコードビルダーを使用して、これらの JSON ファイルを読み取り AI チャットインターフェースを提供するウェブサイトを作成します。

**得られるもの：** あなたのドキュメントのコンテンツによって動かされる、あなたが所有・管理するスタンドアロンウェブサイト。

#### 1.3 既存ウェブサイトに埋め込み可能な AI チャットウィジェットを構築する

**あなたは：** すでにウェブサイト（会社サイト、WordPress ブログ、ポートフォリオなど）を持っていて、AI 駆動の「ドキュメントに質問する」チャットウィジェットを追加したい方。

**やること：** 1.2 と同じですが、完全なウェブサイトを構築する代わりに、ノーコードツールで軽量なチャットウィジェットを構築し、`<iframe>` または `<script>` タグで既存サイトに埋め込みます。

**得られるもの：** 現在のウェブサイトに埋め込まれた AI チャットウィンドウ — 訪問者はサイトを離れることなく PDF コンテンツについて質問できます。

### カテゴリ 2 — 開発者・技術ユーザー

このカテゴリのユーザーはターミナル、Python、JavaScript に慣れており、パイプラインと出力をより細かく制御したいと考えています。

#### 2.1 フルスタック開発者（AI 知識ベース MVP を素早く構築）

**あなたは：** React/Node.js を知っている開発者で、PDF 処理パイプライン全体をゼロから書かずに、クライアントやプロジェクト向けの AI 知識ベースを素早く構築したい方。

**やること：** このリポジトリをクローンし、PDF を `input/` に配置し、パイプラインを実行してウェブサイトを起動します。必要に応じて UI をカスタマイズし、LLM プロバイダーを変更するか、API を拡張します。下記の[クイックスタート](#クイックスタート)セクションを参照してください。

**得られるもの：** チャット、用語集、セクションナビゲーション、ビジュアルアセット検索を備えた、1 日以内に動作する AI 知識ベースウェブサイト — デモまたはデプロイの準備完了。

#### 2.2 AI エージェントを使ってパイプラインのみを実行する（JSON 出力を取得）

**あなたは：** パイプラインから構造化 JSON 出力が欲しいが、ウェブサイトは必要ない開発者またはデータエンジニア。独自の RAG システム、検索エンジン、またはカスタムアプリケーションにデータを供給する予定。

**やること：** 下記の既製プロンプトをコピーして、任意の有能な AI エージェント（ChatGPT、Claude、Manus AI など）に貼り付け、PDF を添付します。AI エージェントが完全なパイプラインを実行し、すべての成果物を含む `PDF_PROJECT_OUTPUT/` フォルダを生成します。

**得られるもの：** 4 つの主要 JSON ファイル（`page_chunks.jsonl`、`glossary.json`、`sections.json`、`visual_assets_index.json`）と評価質問、システムプロンプト、ビジュアルアセットメタデータ — すべてのプログラミング言語で読み取り可能な標準 JSON 形式。

> **このユースケースのコピー&ペーストプロンプト：** [`docs/PROMPT_PIPELINE_ONLY.md`](docs/PROMPT_PIPELINE_ONLY.md) を参照

#### 2.3 AI エージェントを使ってパイプラインとウェブサイトを構築する（エンドツーエンド）

**あなたは：** AI エージェントにすべてを行わせたい開発者、創業者、または技術ユーザー — 単一セッションで PDF を処理し、完全なデプロイ可能な AI 知識ベースウェブサイトを構築します。

**やること：** 下記の既製プロンプトをコピーして有能な AI エージェント（Manus AI、Claude Cowork など）に貼り付け、PDF を添付します。AI エージェントが完全なパイプラインを実行し、JSON データを生成し、AI チャット、用語集、セクションナビゲーション、ビジュアルアセット検索を備えたインタラクティブウェブサイトを構築・デプロイします。

**得られるもの：** チーム、クライアント、または視聴者と共有できる完全に機能する AI 知識ベースウェブサイト。

> **このユースケースのコピー&ペーストプロンプト：** [`docs/PROMPT_PIPELINE_AND_WEBSITE.md`](docs/PROMPT_PIPELINE_AND_WEBSITE.md) を参照

#### 2.4 バックエンド/データエンジニア（パイプラインのみ、独自フロントエンドを構築）

**あなたは：** すでにフロントエンドまたはアプリケーションを持つ Python 開発者またはデータエンジニア。信頼性の高い PDF から構造化データへのパイプラインだけが必要。

**やること：** `pipeline/` ディレクトリのみを使用します。ローカルマシンでスクリプトを実行します。出力 JSON ファイルは Python、PHP、Go、Java、Ruby など JSON を読み取れるあらゆる技術スタックに統合できます。

**得られるもの：** ページレベルのテキストチャンク、用語集、セクション階層、ビジュアルアセットメタデータを含む、クリーンで構造化された JSON データ — 既存システムにプラグインする準備完了。

## 機能一覧

| 機能 | 説明 |
|------|------|
| **Gemini Vision 分析** | すべての図表、表、画像が Gemini Vision によって詳細な空間的説明で分析される |
| **引用付き AI チャット** | 質問してドキュメントに基づいた回答を取得、ページ番号引用付き |
| **ビジュアルアセット検索** | 関連する図表がチャット回答の横に自動表示される |
| **用語集ブラウザー** | カテゴリバッジとページ参照付きのアルファベット順用語集 |
| **セクションナビゲーター** | 要約とキーワードタグ付きの完全な書籍構造 |
| **画像説明** | 「画像説明に変換」ボタンが複雑な回答の AI ビジュアルサマリーを生成 |
| **ダーク/ライトテーマ** | ダークモードとライトモードを切り替え |
| **PDF アップロードデモ** | 新しい PDF をアップロードして処理するための内蔵インターフェース |

## クイックスタート

> このセクションは**開発者**（ユーザータイプ 2.1 および 2.4）向けです。非技術ユーザーの方は上記の[カテゴリ 1](#カテゴリ-1--非技術ユーザーコーディング不要) を参照してください。

### 前提条件

| 要件 | バージョン | 用途 |
|------|-----------|------|
| Python | 3.9+ | パイプラインスクリプト |
| Node.js | 18+ | ウェブサイト |
| pdftotext | 任意 | テキスト抽出（`sudo apt-get install poppler-utils`） |
| Gemini API キー | — | Vision 分析とチャット（[無料キーを取得](https://aistudio.google.com/app/apikey)） |

### ステップ 1：リポジトリをクローン

```bash
git clone https://github.com/dev-james0723/DocOracle.git
cd DocOracle
```

### ステップ 2：PDF を配置

```bash
cp /path/to/your/book.pdf input/
```

### ステップ 3：パイプラインの依存関係をインストール

```bash
pip install -r pipeline/requirements.txt
```

### ステップ 4：API キーを設定

```bash
export GEMINI_API_KEY="your-gemini-api-key"
```

### ステップ 5：パイプラインを実行

```bash
bash pipeline/run_all.sh
```

パイプラインは PDF を 12 のステップで処理します。処理時間はページ数によって異なります：

| ページ数 | 推定時間 |
|---------|---------|
| 50 | ~15 分 |
| 200 | ~1 時間 |
| 500 | ~3 時間 |

### ステップ 6：ウェブサイトを起動

```bash
# 4 つの主要出力ファイルをウェブサイトにコピー
cp output/05_retrieval/page_chunks.jsonl website/server/data/
cp output/04_gold_master/glossary.json website/server/data/
cp output/04_gold_master/sections.json website/server/data/
cp output/10_visual_assets/visual_assets_index.json website/server/data/visual_assets.json

# ウェブサイトをインストールして起動
cd website
npm install
npm run dev
```

ブラウザで `http://localhost:3000` を開きます。AI 知識ベースの準備完了です。

## パイプラインステップ

パイプラインは順番に実行される 12 の Python スクリプトで構成されています：

| ステップ | スクリプト | 機能 |
|---------|-----------|------|
| 1 | `01_build_inventory.py` | すべてのページをテキスト、図表、写真、または混合に分類 |
| 2 | `02_generate_page_records.py` | Gemini Vision を使用して各ページの詳細レコードを作成 |
| 3 | `03_merge_all_records.py` | テキスト抽出とビジョン分析をゴールドマスターレコードにマージ |
| 4 | `04_build_visual_summary.py` | 高リスクビジュアルページのサマリーを生成 |
| 5 | `05_build_sections_glossary.py` | 章/セクション構造と用語集を構築 |
| 6 | `06_build_glossary_faq.py` | コンテンツから FAQ シードを生成 |
| 7 | `07_build_retrieval.py` | RAG 用の検索最適化チャンクを作成 |
| 8 | `08_build_eval.py` | テスト用に 80+ の評価質問を生成 |
| 9 | `09_identify_visual_pages.py` | 図表、表、または画像を含むすべてのページを特定 |
| 10 | `10_build_visual_assets.py` | ビジュアルアセットを個別の画像として抽出 |
| 11 | `11_build_visual_metadata.py` | 各ビジュアルアセットと説明的なメタデータをペアリング |
| 12 | `12_build_url_map.py` | ウェブ表示用の URL マッピングを構築 |
